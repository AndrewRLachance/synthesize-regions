# Core Templates Catalog Architecture

`@synthesize-regions/core-templates` is a caller-owned companion package for
the `synthesize-regions` engine. The engine owns template contracts, graph
compilation, validation, and identity algorithms. This package owns curated
template definitions, catalog membership, dependency compatibility, metadata,
and catalog-specific verification.

## Public catalog surfaces

- `.` and `./curated` expose the stable 479-template curated catalog.
- `./effect-v4` exposes all 1,794 canonical templates and a registry constructor.
- `./effect-v4/authoring` exposes the consolidated Effect authoring helpers.
- `./effect-v4/<domain>` exposes named definitions and one combined domain
  array. Leaf source modules are private.
- `./base` and `./es-toolkit` expose non-Effect packs.
- `./drizzle-orm/v1` exposes a standalone 253-template Drizzle ORM v1 catalog,
  its explicit pack registry, and a registry constructor.
- `./metadata/effect-v4.json` and
  `./metadata/effect-v4-replacements.json` expose publishable catalog metadata.
- `./metadata/drizzle-orm-v1.json` exposes the generated Drizzle catalog
  manifest.

## Ownership and assembly

Every canonical `modelId` has exactly one physical domain owner under
`src/packs/`. Each domain `index.ts` exports its leaf definitions and a single
`effectV4<Domain>GraphTemplateInputs` array. Cause definitions are owned by the
core Cause module; compatibility collections may reference them but the
canonical errors pack does not own them a second time.

`src/catalogs/effect-v4-packs.ts` is the only registry of canonical packs. The
canonical catalog flattens that explicit list in order and throws on a duplicate
ID. It does not scan the filesystem or silently filter duplicates. The curated
catalog is assembled independently so its historical 479-template membership
does not drift with the canonical catalog.

The Drizzle catalog is independently assembled under
`src/packs/drizzle-orm/v1`. Its SQL, query, relations, schema, runtime, and
Effect Schema slices are explicit members of `drizzleOrmV1TemplatePacks`.
It is deliberately absent from `effect-v4-packs.ts`, so adding or revising
Drizzle templates cannot silently change either established catalog.

## Generation and evidence

`npm run generate` derives the canonical manifest, replacement metadata,
consolidated audit report, and compact structural evidence. Live values come
from the catalog; historical rewrite data and report prose have package-owned
sources under `scripts/generate`. `npm run generated:check` writes the same
bytes to a temporary directory and compares them with the checked-in outputs.
The check covers counts, unique ownership, marker-to-port integrity,
replacement targets, source paths, and AI-pack inclusion.
The same generator derives the Drizzle manifest from the live pack and checks
its 253 unique IDs, pack counts, versions, marker integrity, and lack of model-ID
collisions with the Effect catalog.

Large or diagnostic-only products belong under ignored `.artifacts/`. The
published package contains `dist/`, metadata, documentation, and its README;
tests, tools, raw inventories, semantic fixtures, and evidence are excluded.

## Compatibility and verification

The package peer-pins `effect` to `4.0.0-rc.117` and declares
`drizzle-orm@1.0.0-rc.4` as an exact optional peer. Other optional peers declare the
platform, SQL, telemetry, OpenAPI, Vitest, es-toolkit, and ts-pattern surfaces
referenced by individual packs. All `src/**/*.ts` files are typechecked.

`npm run verify` checks generated bytes, typechecks, runs catalog and behavior
tests, builds declarations, imports every declared entry point, and inspects the
packed tarball. Module-resolved semantic compilation remains a separate audit
under `tools/semantic-compile`; its recorded baseline contains the two known
genuine AI failures and must not gain additional failures.
